Политика конфиденциальности

ExchangeConnector

Дата: 10 ноября 2026. Программа работает на компьютере пользователя и обращается к Google Calendar только так, как описано ниже.

Кто отвечает

Константин Ушаков, info@makedev.ru, сайт https://makedev.ru/. Отдельной компании-оператора и сервера приложения нет.

Какие данные Google запрашиваются

Единственный scope:

https://www.googleapis.com/auth/calendar.app.created

Он позволяет видеть, создавать, изменять и удалять календари, которые создало это приложение, и события в них. Список остальных календарей аккаунта, основной календарь и чужие события этот scope не открывает.

При входе Google возвращает refresh token. Программа сохраняет на компьютере пользователя только его. Access token не записывается. Код авторизации принимается локально на 127.0.0.1 и на сервер разработчика не уходит.

Как используются данные Google

Данные нужны только для одной функции, которую запускает сам пользователь: держать в его аккаунте Google копию рабочего календаря.

  • Программа создаёт вторичный календарь «Рабочий календарь», если его ещё нет, и запоминает его идентификатор локально.
  • В этот календарь записываются название, начало, конец и признак занятости встречи из Exchange.
  • К событию добавляются закрытые свойства tcbSource=exchange и tcbSyncKey. Они нужны, чтобы узнавать свои события и не менять остальные.
  • Перед изменением или удалением программа читает событие и проверяет метку. Без метки событие не меняется.
  • Если встреча пропала из текущего окна Exchange, а её прежний интервал это окно ещё пересекает, копия в Google удаляется. Встреча, которая просто ушла в прошлое за границу окна, в Google остаётся.

Описание, участники, организатор, место, вложения, ссылки на созвоны и напоминания в Google не отправляются. Публичная ссылка и общий доступ к календарю не создаются.

Данные Google не продаются, не передаются рекламным или аналитическим службам и не используются для рекламы. Разработчик не получает содержимое календаря и не читает его на своей стороне: запросы идут с компьютера пользователя в Google Calendar API.

Что читается из Exchange

Источник — календарь Exchange, к которому пользователь сам подключает программу. Читаются только папка календаря и события в окне 7 дней назад и 60 дней вперёд. Из события берутся название, время, признак «весь день», занятость и идентификаторы, нужные для сопоставления повторений. Пароль Exchange спрашивается локально и хранится в Windows Credential Manager. В Google он не отправляется. Запись в Exchange не выполняется.

Где это хранится

  • Копия встреч — в календаре Google пользователя.
  • Refresh token и пароль Exchange — в Windows Credential Manager, служба exchange-gcal-bridge, на том же компьютере.
  • Локальный файл состояния хранит идентификатор календаря, идентификатор события Google, служебный ключ, интервал и хеш содержимого. Текст названия в этот файл не пишется. Хеш считается от названия, времени, признака «весь день» и занятости, чтобы заметить изменение.
  • Файл клиента OAuth лежит рядом с локальным конфигом и используется только для входа в Google.

Как долго хранится

События остаются в календаре Google, пока их не удалит синхронизация по правилу выше или сам пользователь. Refresh token хранится, пока пользователь не удалит его из Windows Credential Manager или не отзовёт доступ в Google. Локальный хеш хранится, пока существует файл состояния.

Как отозвать доступ и удалить данные

  • Отозвать доступ приложения: https://myaccount.google.com/permissions. После отзыва программа теряет возможность читать и менять свой календарь. Уже созданный календарь и события остаются в аккаунте, пока пользователь их не удалит.
  • Удалить копию встреч: удалить календарь «Рабочий календарь» в Google Calendar.
  • Удалить локальные секреты: убрать учётные данные службы exchange-gcal-bridge в диспетчере учётных данных Windows и удалить каталог %LOCALAPPDATA%\exchange-gcal-bridge.

Запрос об удалении можно также отправить на info@makedev.ru. На стороне разработчика копии календаря нет, поэтому удаление содержимого выполняется в аккаунте Google и на компьютере пользователя.

English

Effective 10 November 2026. ExchangeConnector is operated by Konstantin Ushakov, info@makedev.ru. There is no application server.

The app requests one Google scope, https://www.googleapis.com/auth/calendar.app.created. It creates a secondary calendar named “Рабочий календарь” in the user’s Google account and writes only the event title, start, end, free/busy status, and two private sync properties (tcbSource, tcbSyncKey). It does not copy descriptions, attendees, locations, or attachments, does not read or modify calendars created by anyone else, and does not share the calendar. Before an update or delete, it reads the event and checks the private marker. Unmarked events are left untouched.

Google user data is used only to keep that personal calendar copy. It is not sold, not used for advertising, and not sent to the developer. The refresh token is stored only in Windows Credential Manager on the user’s computer. A local state file stores calendar and event ids, a sync key, the event interval, and a hash of the copied fields. The event title is not written to that file. The Exchange password is also stored locally and is never sent to Google.

Revoke access at https://myaccount.google.com/permissions. Delete the copied events by deleting the “Рабочий календарь” calendar in Google Calendar. Delete local secrets by removing the exchange-gcal-bridge credentials in Windows Credential Manager and the %LOCALAPPDATA%\exchange-gcal-bridge folder. The developer does not hold a copy of the calendar and cannot delete it remotely.
